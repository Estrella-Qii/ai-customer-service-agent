# v0.1.0 Release Notes (Draft)

> 状态：草案。此版本尚未打 tag 或发布；需要在维护者审核 PR、CI 全绿和容器实跑通过后再使用。

`v0.1.0` 将是项目的第一个可审阅开源节点，目标是提供一条完整、可自托管、可验证的 RAG 客服链路，而不是宣称生产成熟。

## Highlights

- 上传 `.txt`、`.md`、`.pdf` 企业知识文档并写入 Qdrant。
- 使用 LangGraph 编排检索、回答和会话保存。
- 返回检索来源，避免把无依据回答伪装成知识库结论。
- 使用 Redis 保存多轮会话，并在 Redis 不可用时显示内存降级状态。
- 提供实验性的知识缺口检测、草稿生成与人工审核回流。
- 提供 Web 工作台、Swagger API、Docker Compose 和示例知识库。
- CI 覆盖 Lint、单元测试、依赖漏洞审计、Compose 校验和镜像构建。

## Security and reliability

- 上传类型、文件名和大小限制。
- 问题、会话 ID 与治理批次边界。
- 对外错误脱敏；详细异常仅写入服务端日志。
- API 容器以非 root 用户运行。
- 未检测到已提交到当前 Git 历史的常见 API Key / 私钥模式。

## Known limitations

- 没有内置鉴权、多租户和速率限制，不应直接暴露到公网。
- 治理状态仍保存在单实例本地 JSON 中。
- 没有公开的离线效果基准、真实生产用户或使用量数据。
- PDF 解析仍为同步处理，大文件只通过上传字节数限制保护。
- LLM 与 Embedding 的真实端到端结果取决于部署者选择的兼容服务。

## Upgrade notes

- 从 `.env.example` 补充 `MAX_UPLOAD_BYTES` 与 `MAX_QUESTION_CHARS`。
- Compose 使用持久化 Redis 卷，并等待 Redis / Qdrant 健康后启动 API。
- 如果更换 Embedding 模型且向量维度不同，需要备份并重建对应 Qdrant collection。
